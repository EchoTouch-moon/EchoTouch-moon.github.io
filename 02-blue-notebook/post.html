Everything I Re-learned by Writing a Tiny HTTP Server

It fits in two hundred lines. It supports keep-alive, chunked responses, and enough of the spec to serve this very blog. Writing it taught me more about production frameworks than reading any of them ever did.

The socket is not the hard part

accept() gives you a conversation. The hard part is that everyone in your process wants to talk at once. Before you reach for an event loop, count how many conversations a page view actually needs:1

def serve(conn):
    request = conn.recv(64 * 1024)
    path = parse_path(request)
    conn.sendall(render(path))
    # keep-alive: hold the line open, politely
    if wants_more(request):
        serve(conn)

A framework is a very confident answer to questions you have not asked yet.

What buffering taught me about kindness

  • Flush early when users read; batch late when machines do.
  • Timeouts are promises, not suggestions.2
  • Every "temporarily unavailable" is someone's morning coffee interlude.

Try it yourself

Serve a directory in eight lines, then break it on purpose: send partial headers, close mid-body, lie about content length. Each failure is a chapter of the spec you will never forget.
